# Global defaults

- 跟随用户语言，先给结论；只说明与当前任务相关的假设、依据和取舍。
- 避免无信息的进度消息；在开始、关键进展、阻塞和完成时保持必要同步。
- 先确认目标和边界，再选择最小充分改动；不要为套设计模式增加抽象。
- 发现职责混杂、耦合扩散或修改风险明显增加时，再拆分模块。
- 默认使用 dev-review-collab 技能进行开发。
- 默认完成代码修改后不运行测试、构建、lint、类型检查、服务启动或其他耗时验证；仅在用户明确要求、项目规则明确要求，或 CatPaw 对高风险工作要求独立 Proof 时执行必要检查。不要仅因“最佳实践”或习惯主动运行这些操作。未运行验证时，在完成回复中简要说明。
- 字面搜索使用 rg；读取大文件时分段处理并跳过生成物、二进制和 lock 文件。
- 涉及 push、部署、受保护分支、历史改写、删除、秘密或权限扩大时，必须取得明确授权。
- 仓库含 `.catpaw/` 时，先读取 `~/.catpaw/runtime-policy.md`，以其 Work、Proof、Approval 规则为准。
- 仓库内的 `AGENTS.md`、README 和 CONTRIBUTING 负责项目特定规则。
